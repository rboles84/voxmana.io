## Classification meanings

**ACTIVE CURRENT REQUIREMENT** means a current route reads or executes it for preserved behavior. **ACTIVE ONLY BECAUSE OF RETIRED COUPLING** means a preserved route still references it, but only for an obsolete account/Terminal dependency. **RETIRED EXECUTABLE** means callable retired behavior remains in shipped source. **DORMANT FUTURE-READY** identifies retained false-gated or unloaded reactivation machinery; it does not recommend reactivation. **LEGACY MIGRATION COMPATIBILITY** identifies a current compatibility reader/conversion. **NO LIVE CONSUMER** means no call from the current production route graph, even if definitions or references exist in tests or the dormant family. Mixed containers are decomposed below; classification is not based on their names or comments.

## Normalization contract

`normalizePlacementResult` is not a Supabase-only serializer. It clones/spreads the source; normalizes top/adjacent matches; preserves version/model version, source mode, faction/name/world/institution/identity, decree, color/mana weights, confidence/gap, starter preferences, evidence trail, stage history, result/public confidence/alternative states, confidence display mode, model kind, limitations and compatibility version. Missing result data stays null/empty rather than becoming invented scores. Legacy faction fallback and synthetic first top match must be assessed independently of account persistence. Removing all “profile,” “result,” or “save” names would break this protected result contract.

## Exact reset / retake / Forget consequences

1. Begin Again calls `resetLocalFlow` after confirmation; Forget first calls `vm_forgetSavedReading`, then it; retired signout also calls it. `startQuickFlow` separately resets questionnaire fields (`questionnaire.js:48-71`) and does **not** call `resetLocalFlow`. The shared reset clears adaptive/quick/refinement/current-view state and destroys the dossier radar. It does **not** delete v1. Preserve that distinction: an incomplete retake cannot destroy the latest complete saved reading.
2. Reset currently calls `vm_resetInterview`, then writes `terminal-error`, `terminal-status`, `terminal-input` without null checks and calls `updateInterviewControls`, which writes input/submit/status. Removing Terminal DOM before detaching these calls causes current quick/reset/Forget failures.
3. `updateTopbar` also dereferences `tb-identity`, `tb-signout`, `tb-retake`, `tb-avatar`, `tb-name`, `tb-placement`; preserve current callers or replace it before removing auth nodes. See detailed [Archscry chain](archscry.md).
4. Forget only clears v1, session `vm_last_result`, and the shared transient result. It does not clear `vm_profile`, local legacy keys, or the Maze handoff. Boot then has independent profile/handoff fallbacks that can restore and re-cache a reading on reload. This is a **source-proven residual restoration risk**, not a claimed live browser reproduction. The isolated probe proves which keys survive; a later targeted route regression must test actual reload/return.
5. Current session legacy migration returns a normalized reading even when local persistence fails, then removes the legacy key. A future cleanup must verify successful durable persistence before discarding a sole legacy copy. This is a narrow prerequisite to retirement, not permission for a caching project now.
