## 4. Suggested test cases

### Static source and consumer contract

Across the existing 16 `canonicalNavPages`:

1. Assert each page loads the amended shared `vm-topbar.js` and `topbar.css` cache query expected for this candidate.
2. Assert consumer changes are cache-query-only; runtime-generated Tools markup should not be duplicated into each page.
3. Assert the shared runtime contains one stable Tools injection owner and one mobile group projection owner.
4. Preserve the five-entry `data-vm-nav` primary order. Tools is a disclosure after Apocrypha, not a current-page destination; use an explicit relative-order/source assertion rather than adding Tools to `getDesktopNavOrder` unless the implementation intentionally changes that helper contract.
5. Preserve plain site-navigation semantics. Do not introduce `role="menu"` or `role="menuitem"`.
6. Assert exact desktop and mobile order: Apocrypha, then Color Pie, then Deck Explorer within Tools; the mobile Tools group appears after the primary Apocrypha link and before Guide.
7. Assert Color Pie uses `https://colorpie.voxmana.io/` and Deck Explorer uses `https://manascope.voxmana.io/`; both use `target="_blank"`, `rel="noopener noreferrer"`, decorative `aria-hidden="true"` `↗`, and visually hidden ` (opens in a new tab)` text.
8. Assert exactly one desktop and one mobile instance of each Tools external link in rendered DOM, with no duplicate injection after repeated initialization or resize.
9. Preserve the first five Home directory cards exactly and the existing six-card Home directory assertions.

### Focused rendered interaction

Use actual rendered controls. For pointer cases, obtain the live control rectangle and use `page.mouse` movement/click rather than DOM `.click()` or handler invocation. For keyboard cases, use `page.keyboard` and focus the actual trigger.

1. **Initial closed state:** Tools trigger has truthful accessible name, controls the disclosure, and reports `aria-expanded="false"`; the panel is not visible and neither external link enters sequential focus order.
2. **Pointer open:** one real pointer click opens exactly one Tools panel and synchronizes trigger state, panel state, and DOM visibility.
3. **Enter open:** from a reset closed state, focus the trigger and press Enter once; the disclosure opens once without double toggle.
4. **Space open:** from a reset closed state, focus the trigger and press Space once; the disclosure opens once without scrolling or double toggle.
5. **Panel focus order:** Tab reaches Color Pie and then Deck Explorer in that order with visible focus.
6. **Escape:** with focus inside the panel, Escape closes Tools, removes both links from sequential focus, reports `aria-expanded="false"`, and restores focus to the Tools trigger.
7. **Outside pointer:** a real pointer click outside both disclosure and trigger closes Tools without stealing focus back to the trigger.
8. **Focus departure:** Tab beyond the final Tools link closes the disclosure while preserving focus on the next valid control. The panel must not trap focus.
9. **Mutual exclusion, Tools first:** open Tools, then open the existing utility menu; Tools closes and the utility menu alone remains open.
10. **Mutual exclusion, utility first:** open the utility menu, then open Tools; the utility menu closes and Tools alone remains open.
11. **Hidden-focus prevention:** before open and after each close path, sequential keyboard traversal never lands on the hidden Tools links. Assert the user-observable focus contract rather than prescribing `hidden`, `inert`, `display:none`, or a specific implementation.
12. **Resize reset:** open Tools at `1440`, resize across the current `1040px` mode boundary to `390`, and assert the desktop disclosure is reset closed with no hidden desktop focus target. Open the utility menu and assert the mobile Tools group sits after Apocrypha and before Guide, contains Color Pie then Deck Explorer exactly once, preserves external-link semantics, and creates no horizontal overflow. Resize back to desktop and assert no stale mobile or desktop open state survives.
13. **Representative composition:** repeat the minimal structure/open/close, focus exclusion, and overflow observations on Apocrypha so Home-specific CSS cannot conceal a core-route regression. Do not duplicate the entire interaction sequence on every route.

Do not follow either external destination during the browser test. Their separately hosted application behavior remains outside VM-701; DOM destination and safety/accessibility attributes are the candidate contract.
